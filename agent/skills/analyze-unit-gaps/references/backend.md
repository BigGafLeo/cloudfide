Backend unit analysis: prioritize service/repository/config/validator/mapper contracts. Database/Express dependencies are outside the unit. Inspect existing assertions, not just coverage: schema optional/null/empty boundaries, isolated env precedence and error propagation. For coercion, normalization or unknown-key stripping claims, name a concrete transforming input and its exact expected downstream value so raw forwarding would differ. For SQL passed to a mock, distinguish contractual columns/constraints from layout; whitespace is not a schema guarantee. For generated API documents, presence alone misses empty content; identify required meaningful fields from supplied contracts. Do not claim real database idempotency from a mocked DDL call. Preserve existing coverage thresholds.

Keep DDL claims proportional to asserted columns, CHECK predicates and defaults; identify missing defaults only when the case promises their compatibility. Avoid formatting-dependent token matches. For encoded configuration values, choose inputs and raw encoded expectations that remain discriminating despite URL-parser normalization; decoded equality can conceal missing encoding.
