# Cloudfide unit-test agent

The controller analyzes unit-test gaps, writes test-only proposals and executes the proposed tests in isolated GitHub jobs. It supports the unmodified Codex and Claude Code CLIs through a small ProviderAdapter interface. The analyst, writer and optional fresh reviewer each load their own skill and only the selected frontend/backend references.

CI runs without model credentials. The privileged workflow uses controller code from the default branch, resolves the PR through GitHub's API and permits model calls only for explicitly trusted same-repository authors. It precollects exact base/head results in a separate job for both automatic and manual triggers. This costs an extra measurement after ordinary CI, but avoids trusting PR-controlled CI payloads. The model receives bounded source data; it has no repository tools. A separate verifier validates and applies the test-only patch, runs both applications' unit tests, typechecks and coverage, then publishes a PR comment and downloadable proposal. It never pushes a generated change.

Application commands run in private, unprivileged containers using a digest-pinned Node 24.13.1 image. Only the disposable application directory is writable; the optional Stryker runtime is mounted read-only. Controller files, credentials, output and the Docker socket are absent. Unit, typecheck, coverage and mutation runs have no network; installation and explicit Prisma generation can use network access. Each container is removed after success, failure or cancellation. Reports must be bounded regular files, with links rejected.

## Setup

Use Node 24.13.1 on Linux. In agent/, run npm ci --ignore-scripts, npm run build and npm test. Native versions and lockfiles live in agent/native/. After npm ci --prefix native --ignore-scripts, run the pinned official Claude installer: node native/node_modules/@anthropic-ai/claude-code/install.cjs. Arbitrary lifecycle scripts remain disabled. The local agent/config.json prepares the owner demonstration for BigGafLeo: analyst/writer claude-sonnet-5-5, optional reviewer claude-opus-5-5, all with subscription authentication. Review and mutations remain off. For your own repository, copy config.example.json and replace its author placeholder; supply your own authentication and conformance evidence.

The mechanical checks require Docker on the Linux runner; the workflows pull the exact pinned image. There is no host-execution fallback. Local probes can also use Docker Desktop.

For this public Cloudfide PR workflow, use Claude subscription authentication if avoiding model API billing. Run the official claude setup-token flow and configure the repository-scoped CLAUDE_CODE_OAUTH_TOKEN secret. The controller invokes the unmodified official CLI. Account allowances still apply; no automatic paid API fallback exists. [Claude authentication](https://code.claude.com/docs/en/authentication) and [GitHub Actions guidance](https://code.claude.com/docs/en/github-actions) document this route.

Codex subscription access remains suitable for personal local CLI use. The [advanced Codex account-auth CI guide](https://learn.chatgpt.com/docs/auth/ci-cd-auth) excludes public/open-source repositories. Use explicit Codex API authentication for this public PR workflow. The implemented self-hosted subscription route is only for that guide's trusted private-automation scope. GitHub entry points now require API-confirmed matching repository identity and private visibility for every active Codex subscription role, including an enabled reviewer; public or unknown visibility is rejected before model calls.

For applicable private automation, use a dedicated CODEX_SUBSCRIPTION_HOME with official Codex login, serialized access and retained native credential refresh. SIGINT/SIGTERM await process completion and cleanup. After an uncatchable kill, stop the sole runner stream before operator recovery; the adapter never steals an existing lock. Do not reuse or repeatedly restore a desktop session seed.

Read [README.md](README.md#authentication-and-provider-policy) for the policy comparison, exact runner placement, Anthropic restrictions on brokering credentials/services and the configured owner profile with per-run limits. Its provider guidance supersedes earlier public-CI subscription recommendations. API authentication requires an explicit auth api selection and is separately billed.

Before enabling a provider, execute node dist/scripts/native-conformance.js PROVIDER MODEL in agent/ on the pinned Linux runtime with its dedicated authentication. Commit only the resulting non-secret conformance record after reviewing the probe. Unknown capabilities or missing credentials produce an inconclusive result. Subscription runs obey account limits. Dollar reservations bound estimated usage admission, not invoices or subscription quotas; calls, output and deadlines are also capped.

Deploy the reviewed controller/workflows to the default branch first. Then open a separate missing-tests PR and manually dispatch Unit-test agent with its PR number. Automatic analysis follows CI on later PR updates. Download the agent artifact, extract payload.json and write its patchText to candidate.patch; inspect it before applying with git apply. Results bind the full tested SHA, control revision, execution run/attempt and artifact digests.

Follow [docs/github-first-run.md](docs/github-first-run.md) for the exact bootstrap and first coverage-gap PR sequence.

## Verification and optional checks

Standard mode needs at most two native calls. Deep mode enables a fresh reviewer (including a different provider) and/or scoped Stryker checks. Both default off and support advisory or required execution gates. The reviewer assesses our tests, not general PR code. Arbitrary model claims remain unconfirmed. Mutation survivors are reported separately from tool errors and are not automatically labelled production defects.

The aspirational objective is 100% of the existing measured scope, without source/config/exclusion changes. Coverage is execution evidence, not proof of complete assertions. Each phase has strict schemas, byte limits, test-file allowlists and an inherited deadline. The proposal is an artifact, not an automatic commit.
